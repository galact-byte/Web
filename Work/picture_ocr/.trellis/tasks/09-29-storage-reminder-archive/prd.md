# 存储提醒与项目归档

## 背景

用户主要使用网页版。网页版数据存在浏览器用户目录（默认 C 盘），随项目增多持续增长。用户不会主动记得去清理或迁移，担心某天 C 盘被占满。

现状（代码核对）：

- 存储设置只显示 `navigator.storage.estimate()` 的「已用 / 总量」总数，没有按项目的占用明细。
- 网页版从未调用 `navigator.storage.persist()`，数据属于 best-effort：磁盘紧张时浏览器可以不经提示整体清除 `127.0.0.1:51730` 来源下的数据。
- 现有「导出数据包 → 手动删除」可以达到归档效果，但两步都靠人记、靠人做；网页版导出走浏览器下载，默认落在 C 盘「下载」目录，对释放 C 盘无效。
- 桌面版数据目录可迁移到其它盘，但同样没有任何主动提醒。

## 目标

「不用记」：由工具自己发现需要清理的时机并提醒，用户只需一键确认；清理过程绝不丢数据。

## 需求

### R1 持久存储（保底）

- 启动时申请持久存储；存储设置中显示当前是否已获批准。
- 未获批准时给出可操作的说明（例如安装为应用后通常会批准），不反复打扰。
- 桌面版同样调用并显示状态（行为以实测为准）。

### R2 占用明细

- 存储设置中列出按占用排序的系统清单：所属项目组、系统名、图片张数、图片占用、最后修改时间、是否已归档。
- 统计不得通过全量读取项目文档或图片字节实现（大库会卡死，见既有约束）。

### R3 主动提醒

- 打开项目列表时后台检查，满足任一条件即在列表顶部显示非阻塞提示条：
  - 本工具占用超过阈值（默认 2GB）；
  - 数据所在磁盘剩余空间低于阈值（默认 10GB）；网页版为浏览器给出的近似值，桌面版为数据目录所在磁盘的实际剩余；
  - 存在超过 N 天（默认 90 天）未修改、且未归档、且有图片的系统。
- 提示写明具体情况（如「5 个系统超过 90 天未修改，共占 1.2GB」）并提供「去归档」入口。
- 「稍后提醒」后 7 天内不再显示同类提示；情况明显恶化（如磁盘剩余跌破更低的紧急线）时不受稍后提醒限制。
- 阈值可在存储设置中修改。

### R4 归档

- 可在提示条入口或存储设置/项目列表中选择要归档的系统（支持一次选择多个、按项目组整组选择）。
- 用户选择保存目录（网页版在支持的浏览器中直接选 D 盘等目录；桌面版用系统目录选择框）；每个系统生成一个数据包文件。
- 写入后读回校验：图片数量、图片 id、每张图片内容与本地一致。全部通过才删除该系统的本地图片字节；任一项失败则该系统不删除、如实报告原因，其余系统不受影响。
- 归档后系统仍留在项目列表，标记「已归档」，显示归档时间、文件名、图片张数与大小；项目组、系统元数据保留。
- 已归档系统整体只读：不能打开编辑、不能添加/删除图片、不能导入合并、不出现在手机采集的系统列表中，需先恢复（避免与归档文件分叉）。
- 浏览器不支持目录选择时，不提供归档（见决策 4），绝不退化为下载到 C 盘后删除本地数据。

### R5 恢复

- 已归档系统可「恢复」：选择对应归档文件，校验与该系统匹配后，原样写回图片（不重新压缩、不改变 id），恢复后取消「已归档」标记。
- 文件不匹配（不是这个系统的归档）时拒绝并说明。

### R6 完成后的说明

- 归档完成后告知释放了多少数据；并说明浏览器回收磁盘空间可能有延迟，「已用」数字不一定立即下降。

## 约束

- 网页版与桌面版都必须实现并分别验证（#57）。
- 所有写用户数据的 IndexedDB 路径经 `trackWrite()`，并补 `verify-pending-writes.mjs`（#70）。
- 列表只读轻量摘要，写/删在同一事务内维护摘要（#60）。
- 存储自检不得把「已归档而本地无图片字节」误报为缺失图片，也不得用删除记录让自检变正常（#91）。
- 恢复写回的图片必须保持原始字节，不得降低导出报告清晰度（#58）。
- CSP `connect-src 'self'`：Blob/data URL 转换不能用 fetch（#43）。
- 提示与确认统一用 `useToast()` / `useConfirmDialog()`（#8）。

## 验收标准

- [x] 网页版启动后申请持久存储，存储设置显示批准状态；桌面版显示对应状态。
- [x] 存储设置显示按占用排序的系统清单，数字与实际图片字节一致（误差仅来自 Base64 估算）。
- [x] 分别构造「占用超阈值」「磁盘剩余低于阈值」「久未修改」三种条件，列表顶部各自出现正确提示；「稍后提醒」7 天内不再出现；紧急线突破时仍出现。
- [x] 网页版（Chrome/Edge）与桌面版：归档到非 C 盘目录，文件存在且可被现有导入功能导入；本地该系统图片字节被删除，列表显示「已归档」。
- [x] 人为破坏归档文件（截断/替换一张图）时，校验失败，本地数据不被删除，提示原因。
- [x] 恢复后图片张数、id、字节与归档前完全一致；导出 Word 报告清晰度不变。
- [x] 用错误文件恢复被拒绝。
- [x] 存储自检对已归档系统不报缺失；归档/恢复过程中关窗受未完成写入保护。
- [x] `npm run build` 与相关 verify 脚本全绿。

## 已确认决策（2026-09-29）

1. 归档文件为明文 ZIP（与现有「导出数据包」同格式，可被现有导入功能直接导入），恢复不依赖密码。
2. 已归档系统整体锁定：图片与文字内容都不可修改，需先恢复再编辑。
3. 默认阈值：本工具占用 2GB、磁盘剩余 10GB、久未修改 90 天、「稍后提醒」7 天；紧急线（不受稍后提醒限制）为磁盘剩余 3GB。均可在存储设置中修改。
4. 网页版浏览器不支持目录选择（非 Chrome/Edge）时，不提供归档，提示改用 Chrome/Edge 或继续使用现有导出；不做「下载到 C 盘再删本地」的退化路径。
