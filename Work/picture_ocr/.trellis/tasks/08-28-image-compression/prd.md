# 图片入库压缩与存量图片瘦身

## Goal

手机拍照原图 6-8MB 直接以 base64 存入 IndexedDB，单个系统上百张图可达数百 MB（实测导出包 445MB / 123 张，其中 96 张手机 12MP 照片占 99% 体积），导致「返回项目」把整包 data URL load 进内存、「导出报告」把整包嵌进 Word，都会卡顿。目标是在图片入库前等比压缩，并提供对现有大图的一键批量瘦身。

## Requirements

- 入库压缩：图片进入 IndexedDB 之前统一走等比压缩（长边 1920px、JPEG 质量 0.82），覆盖三处入口：
  - 手机局域网上传（`LanMobileCollector` 上传前，同时省去网络传输原图）
  - 手机网页相机拍照（`captureCameraFrame`，当前是全分辨率 0.92）
  - 电脑端直接导入图片（`imageFiles.readImageFile`，拖拽/粘贴/选择文件）
- 存量瘦身：电脑端提供「压缩现有图片」批量操作，就地把已存大图重编码变小，保留图片 id / fileName / caption / uploadedAt，仅在能变小时替换，压缩后报告节省的数量与体积。
- 智能跳过：已经足够小的图（长边 ≤ 1920 且体积低于阈值，如 ~600KB）不重复压缩；压缩结果不小于原图时保留原图。
- 方向修正：保留 EXIF 方向（手机照片带旋转标记），压缩后不得出现横竖颠倒。
- 两条运行路径（Electron 与 Web ZIP）均生效：压缩放在共享前端，服务端保持 relay-only，不改 `lanServer.cjs` / `start-server.ps1`。

## Acceptance Criteria

- [ ] **导出报告图片能看清**（唯一硬指标）：手机 12MP 屏幕照片压缩后，导出 Word 报告中日志文字、时间戳、明细文字清晰可读。
- [ ] 手机上传一张 12MP 照片，落库图片长边 ≤ 1920px、体积显著下降（目标 ≤ ~800KB）。
- [ ] 电脑端导入大图、网页相机拍照，同样被压缩。
- [ ] 对现有大图执行批量压缩后：整体体积明显下降（实测 445MB 数据集目标降到约 1/6~1/8），图片张数不变、id 不变、报告仍清晰。
- [ ] 手机照片方向正确，无横竖颠倒。
- [ ] `tsc` / 构建通过；Electron 与 Web ZIP 采集与导出流程仍正常。

## Notes

- 压缩参数经真实样本验证：3072×4096 5391KB→486KB、4096×3072 8177KB→654KB（约 1/8~1/12），文字零损失。
- 已确认 Electron `lanServer.cjs` 与 Web ZIP `start-server.ps1` 均为 relay-only（原样 base64 转发），故压缩集中在前端一处即可覆盖两条路径。
