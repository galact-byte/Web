# 技术设计（已确认并实施）

## 边界

改动集中在 `ProjectList.tsx`、`components/project-list/` 和 `App.tsx` 的列表 UI 状态接线。复用既有 DB、导入导出、图片压缩、确认框与 LAN 回调，不增加依赖，不改数据库版本或用户数据。

现有 `ProjectTableRow.tsx` 不被 `ProjectList.tsx` 使用且缺少压缩/采集能力；实施时优先沿用并整理当前实际行渲染，不直接切回旧组件。

## 视图与数据流

`listProjectGroups()` → 纯分类/过滤派生 → 项目列表、独立系统列表或组内系统列表。

- 真实 group 存在：归项目页，包含零/一个/多个系统的组。
- group 缺失但系统存在 groupId：归项目页异常分组，明确标注；禁用依赖真实组记录的添加/编辑/删除组操作，允许系统级操作。不得因 `group === null` 将其误判为独立系统。
- 无 groupId：归独立系统列表。
- 最近更新取组与系统 updatedAt 最大值，保持现有时间降序；独立系统按 updatedAt 降序。
- 分类、计数、搜索只基于 `ProjectGroupSummary` / `ProjectSummary`；异常组单独标示数量，不能计成真实项目组。

## UI 状态生命周期

在 `App` 持有可恢复的列表视图状态，通过明确 Props 交给 `ProjectList`，跨 `projectListRefreshKey` 重挂载保留。视图类型使用判别联合，覆盖项目页、独立页、组详情；按列表位置保存搜索和滚动值。保存的是 UI 标识和数值，不缓存项目文档/图片，不写 IndexedDB。

批量选择、菜单、导入对话框与执行中状态留在列表内部。切换范围或搜索时清空选择；执行删除前再次求可见系统与选择 ID 的交集。项目组顶层没有系统级全选框。

组内返回项目页恢复之前搜索及位置；工作区的已有 `/project/<id>` 路由保持，返回使用 App 中保存的列表位置。页面刷新不承诺恢复所有临时 UI 状态；直接打开工作区 URL 后返回使用合理默认列表。无效组 ID 在加载成功后退回项目页；加载失败时显示错误，不当作组已删除。

## 搜索与新建

每个列表位置保存自己的搜索。项目页搜索项目字段与子系统字段，只展示匹配项目，进入项目后使用独立的组内搜索；独立页与组内页逐系统匹配。

保留现有新建表单：一个系统保存独立文档，多个系统创建组。复用创建函数返回 ID，在刷新完成后定位结果，清空目标视图的搜索，避免新数据被过滤。添加系统仍限当前真实项目组。

## 操作与视觉

沿用 slate/blue/red、Tailwind、既有间距和表格风格，不重做全局字体。表头和行共用对应网格模板，给名称与单位腾出空间。低频操作在所有宽度统一收纳；窄屏可将手机采集收进更多，保证可达与不溢出。至少检查 375、768、1440px。

组级采集调用现有 `onStartLanCollector(groupId, title, systemIds)`；系统级只传该 systemId，保留原 groupId。不重新实现 LAN 会话，不修改手机端协议。

优先复用原生 disclosure/语义按钮实现更多操作，并补单菜单展开、选择后关闭、外部点击关闭、Escape 与焦点恢复。若使用 ARIA menu 模式，须完整实现箭头键导航，不能只挂 role。删除与压缩继续使用现有确认框和错误处理。

菜单内容初始即固定定位且隐藏，避免原生 details 首次展开时挤动文档；toggle 时测量锚点与窗口剩余空间，支持向上展开。监听仅在菜单展开时注册并在 cleanup 移除。

## 兼容与风险

- `scripts/verify-lan-mobile-picker.mjs:43` 起锁定旧网格字符串和“宽屏全部按钮”。需要更新被方案明确替代的布局断言，保留 LAN、路由、响应式能力断言，并用行为测试覆盖新结构，不能删除整段验证求绿。
- `App.tsx:317` 返回会重新挂载列表，不能只在列表内部加 state 就声称实现恢复。
- 现有加载后自检提示与延迟图片迁移 effect 必须保留，不能因进入项目详情反复重新挂载列表而重复触发。
- 验证使用隔离浏览器上下文和 Electron 临时 userData；不得对用户真实项目做删除、压缩或导入测试。

本任务只改变展示和 UI 状态，回退任务代码即可恢复旧页面，不涉及数据回滚。保留原工作区路由和存储 API，避免版本兼容负担。
