# 技术设计（已批准实施）

## 最小变更

1. 在现有诊断导出添加异常记录取证元数据，不新增恢复按钮。由 db.ts 独立只读函数接收异常主键，使用 images.by_project.count(id) 统计关联记录，不读取 Base64。返回每个 ID 的 count/status 与该 ID 的迁移状态；失败和不支持显式区分，不以 0 兜底。
2. 保持 repair/damagedIds/damagedRecords 既有契约；新信息在诊断报告独立可选字段中表达。不再次调用可写的自检来取图片统计。迁移状态仅附相关 ID 的状态，不输出整个 localStorage。
3. migrateProjectImages 分开“记录不存在”和“存在但值无效”。null 或非对象不可当成正常跳过；批量迁移保留失败报告，其他有效项目继续。重试时将已知异常 ID 从旧 completedIds 排除，使历史误判可修正；重检确认前不删除原文档或图片。
4. reconcileProjectImages 遇到无法判断的文档时返回明确失败/不可检查，不使用两个空数组伪装一致。该函数尚无应用调用者，不扩展 UI 为全库对账。

## 安全与兼容性

- DB_VERSION 维持 5，store 和图片格式不变；网页和 Electron 使用同一逻辑。
- 诊断统计为 readonly，单条失败保留错误且不影响其他记录，不加载整库文档或图片。诊断导出使用 listDiagnosticProjectGroups 绕过普通列表的回填/迁移；getStoreDiagnostics 同样使用不带版本的诊断打开。数据库不存在时中止 onupgradeneeded，不建库；超时、abort 和迟到连接均释放资源。
- 数据库不存在、索引缺失、超时或迁移状态格式错误均为明确状态。
- 不把关联记录数量称为可恢复图片数；只有取出并验证图片字节后才可作恢复结论。
- 不改变现行备份保留时间；本次通过操作步骤先保全，后续若修改清理策略需单独确认范围。
- 实际恢复只在完整副本分析后另行制定，禁止空项目覆盖、删异常记录或猜测资产归属。

## 回退与验证边界

无需数据迁移，代码回退不能降低数据库版本。模拟 null 返回值可验证程序分支，但不能代替真实 Electron 数据库损坏复现。先验证普通原生 IDB 的正常/缺失路径，再以受控返回值模拟异常路径；不得为构造 null 测试库擅自改变真实 keyPath 契约。
