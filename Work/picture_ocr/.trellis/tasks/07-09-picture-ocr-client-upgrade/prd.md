# Picture OCR multi-project client upgrade

## Goal

将现有测评证据采集工具从单项目浏览器页面升级为支持多项目管理、项目级元数据、便捷资产编辑、改进导入合并、改进报告命名，并提供更适合同事使用的客户端交付形态。

## Background / Confirmed Facts

- 当前应用是 React 18 + Vite + TypeScript 纯前端应用，无后端服务。
- 当前持久化使用浏览器 IndexedDB，`src/utils/db.ts` 只保存一份 `id: "current"` 的 `ProjectDocument`。
- 当前 `ProjectMeta` 包含 `projectName`、`unitName`、`evaluator`、`reportDate`。
- 当前左侧资产在 `src/components/Sidebar.tsx` 中通过重命名按钮进入编辑态，还不支持双击资产名编辑。
- 当前默认分类在 `src/data/defaults.ts`，其中“管理层面”是 `freestyle` 且默认无预设材料。
- 当前 Word 导出文件名在 `src/utils/wordExport.ts` 中为 `测评证据报告_${unitName}_${date}.docx`。
- 当前 ZIP 数据包导入导出在 `src/utils/exportImport.ts`，合并导入按资产 `id` 合并；用户希望“相同资产”合并到一起，可能需要按分类 + 资产名称兼容合并。
- 当前已提供 Release ZIP + BAT/PowerShell 本地静态服务器方案，但用户进一步要求“再做一个客户端”。

## Requirements

### R1. 左侧资产双击编辑

- 用户双击左侧资产/材料名称时，应进入与点击重命名按钮相同的编辑态。
- 保留现有重命名按钮、Enter 保存、Escape 取消、失焦保存的交互。

### R2. 管理层面默认制度栏

- “管理层面”分类应默认包含一个预设材料/资产：`制度`。
- 新建项目时自动出现该项。
- 兼容旧数据：旧项目没有 `制度` 时是否自动补齐，待设计阶段确认最小风险方案。

### R3. Word 报告文件名规则

- 导出 Word 报告文件名应改为：`项目名称_系统名称_测评证据.docx`。
- 当前数据结构没有单独的“系统名称”字段，需要扩展项目元数据。
- 项目名称为选填；为空时文件名使用安全兜底值，例如 `未命名项目`。
- 文件名需要清理 Windows 不允许的字符，避免下载失败或文件名异常。

### R4. 多项目外层界面

- 应新增项目列表入口，最外层展示一行行项目。
- 用户点击/打开某个项目后进入当前证据采集界面。
- 每个项目应独立保存分类、资产、截图、模板和元数据。
- 首版需要支持创建项目、打开项目、删除项目、搜索项目，以及项目级数据包导入/导出入口。
- 删除项目必须二次确认；首版暂不做复制项目。
- 数据包导入/导出从项目内部工具栏挪到外层项目列表界面，项目打开后的采集界面不再放导入/导出按钮。
- 项目列表每个项目行提供“导入数据包”单一入口；导入弹窗中再选择“覆盖导入”或“合并导入”。

### R5. 项目信息字段扩展

项目打开后，应先填写或可编辑：

- 项目编号（选填）
- 项目名称（选填）
- 单位名称
- 系统名称（为满足报告文件名规则需要）
- 日期（选填）

### R6. 数据包导入导出适配

- 数据包导入/导出入口应放在外层项目列表界面，而不是项目内部采集工具栏。
- 导出数据包应包含所选项目完整数据。
- 覆盖导入/合并导入应以外层项目列表中明确选择的目标项目为准，避免“当前项目”上下文歧义。
- UI 上将“覆盖导入”和“合并导入”合并为一个“导入数据包”按钮，弹窗内选择导入模式。
- 合并导入时，如果遇到相同资产，应合并到同一个资产里。
- 合并导入应尽量避免重复图片；当前代码按图片 `id` 去重，需要保留或增强。

### R7. 粘贴图片目标明确化

- 当前每个检查项的上传区支持 `Ctrl+V` 粘贴截图，但用户需要先聚焦上传区，否则不知道图片会粘到哪里。
- 用户希望点击某个检查项/资产卡片边缘后，该卡片成为当前粘贴目标；之后直接 `Ctrl+V` 就把截图粘到这个目标检查项里。
- 当前粘贴目标应有可见高亮状态，避免误粘。
- 若没有明确粘贴目标，应给出清晰提示或保持现有上传区粘贴方式，不应静默粘到错误位置。

- 技术选型在设计阶段确定，优先选择对当前 React/Vite 项目改动小、GitHub Actions 可构建的桌面壳方案。

## Acceptance Criteria

- [ ] 双击左侧资产/材料名称可以进入编辑态，原重命名按钮行为不退化。
- [ ] 新建项目默认“管理层面”下存在 `制度` 项。
- [ ] Word 导出的文件名符合 `项目名称_系统名称_测评证据.docx`，且非法文件名字符被安全处理。
- [ ] 应用启动先展示项目列表；支持新建、打开、搜索、删除项目，删除前有二次确认。
- [ ] 数据包导入/导出入口位于项目列表界面，导出和覆盖/合并导入都能明确作用到目标项目。
- [ ] 每个项目的数据互相隔离，刷新页面后仍能回到可用的项目列表/项目数据。
- [ ] 项目信息表单包含项目编号、项目名称、单位名称、系统名称、日期；项目编号、项目名称、日期为选填项。
- [ ] 数据包导出/导入仍可用；合并导入遇到同分类同名资产时合并检查项和截图。
- [ ] 点击检查项/资产卡片边缘后，该卡片成为高亮粘贴目标，随后 `Ctrl+V` 可直接把截图粘到该目标中。
- [ ] 内部采集界面在不牺牲功能的前提下参考用户截图优化层级、卡片和上传区视觉；上传框不再做横向长条，改为接近图片缩略图尺寸的紧凑虚线卡片。
- [ ] 客户端可在用户确认的目标平台上完成构建或提供明确的构建流程。
- [ ] `npm run build` 通过。

## Out of Scope Unless Reconfirmed

- 多人协作实时同步或后端服务。
- 权限、账号登录、云端项目库。
- OCR 自动识别图片内容。
- 人员下拉或测评人员字段。
