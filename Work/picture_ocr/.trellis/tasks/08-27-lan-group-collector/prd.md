# 局域网采集升级为项目组级 + 手机端选系统

## 背景

工具用于现场测评取证：一个「测评项目组」下有多个「系统」，测评人员现场逐系统拍照取证。

当前局域网采集会话绑定在**单个系统**的工作台里（`AppContent`）。切换系统会导致 `AppProvider` 按 `activeProjectId` 重挂载、`AppContent` 卸载并触发 `stopSession()`，手机链接立即失效，必须重新扫码。用户反馈：每切一个系统就要重开一次局域网，繁琐。

## Goal

把局域网采集从「系统级」提升到「项目组级」：一次启动、整组通用；手机端可自主选择要采集的系统；切换电脑端当前系统不再中断手机会话。Web ZIP 模式与 Electron 客户端模式行为一致。

## Requirements

- **组级会话**：局域网会话归属于一个项目组，快照携带该组下**所有系统**的结构（系统名、分类、资产、检查项、已同步张数）。
- **手机端选系统**：手机采集页在进入分类/资产之前，先选择目标系统；选定后按现有流程拍照/选图上传。上传请求需携带目标系统标识。
- **切系统不断连**：电脑端在同组内切换、打开、返回系统列表时，手机会话与链接保持有效，不需要重新扫码。
- **任意系统落库**：手机上传的图片写入其目标系统的 IndexedDB，与电脑端当前打开哪个系统无关；若目标正是当前打开系统，工作台需实时反映新图片。
- **快照实时更新**：电脑端修改当前系统结构或有新图片落库后，手机端拉取到的组快照随之更新（至少含张数与结构）。
- **双运行路径一致**：
  - Electron 客户端：`electron/main.cjs` + `electron/lanServer.cjs` + `electron/preload.cjs`（IPC 通道）。
  - Web ZIP：`start-server.ps1`（`/api/control/*` 与 `/api/session`、`/api/upload`）。
  - 两条路径的会话协议、选系统、落库语义保持一致。
- **入口位置**：局域网采集入口在项目组层级可用（外部启动整组会话），不再要求先进入某个系统再开。系统工作台内保留「采集中」状态入口。
- **安全边界不回退**：沿用现有 token 鉴权、图片魔数校验、10MB 限制、私网地址、CSP、会话过期等约束；上传的 `(系统, 资产, 检查项)` 三元组必须在会话快照内校验。

## 非目标

- 不改动图片存储结构、导出逻辑、PWA / 离线能力。
- 不引入跨局域网/公网访问，不加多设备并发写同一系统的冲突合并策略（沿用后写覆盖 + 去重）。
- 不改动项目组/系统的数据模型（`ProjectGroup` / `ProjectDocument`）。

## Acceptance Criteria

- [ ] 电脑端从项目组入口启动一次局域网会话，手机扫码后可在采集页选择该组任意系统。
- [ ] 手机为系统 A 拍照 → 图片写入系统 A 的库；随后切到系统 B 拍照 → 写入系统 B；全程手机链接不失效、无需重新扫码。
- [ ] 电脑端在同组内切换当前打开系统时，手机会话保持运行，链接可继续使用。
- [ ] 手机上传到「电脑端当前打开系统」时，该系统工作台实时显示新图片（张数与缩略图）。
- [ ] 上传到不属于当前会话的系统/资产/检查项被拒绝（沿用 403 语义）。
- [ ] Electron 客户端与 Web ZIP（`start-server.ps1`）两条路径均满足以上行为，且 `scripts/verify-lan-*` / `verify-web-lan-server.ps1` 相关校验通过或据实更新。
- [ ] 现有单系统场景（组内仅一个系统）不出现回退：仍能正常启动、上传、落库。

## Notes

- `LanImageUpload` 已带 `projectId` 字段，`db.ts` 存取按 systemId 独立，协议与落库改造有现成基础。
- 关键风险点在「非当前打开系统的落库」与「当前打开系统的实时刷新」如何统一，详见 design.md。
