# 缓解 C 盘膨胀：桌面版可迁移数据目录 + Web 版存储用量可视与导出可选位置

## Goal

缓解长期使用导致的 C 盘膨胀，覆盖两种部署：

- **桌面版（Electron portable exe）**：让用户数据目录（IndexedDB 里的项目与内嵌 base64 图片）能从默认 `%APPDATA%`（C 盘）迁移到用户自选目录；默认行为不变，迁移是用户主动、可回退、不丢数据的操作。
- **Web / 云平台版**：网页代码无法搬动浏览器自己的 IndexedDB，因此改为两个务实杠杆——**(A) 存储用量可视 + 导出清理引导**、**(B) 导出/备份时可选保存位置**（支持的浏览器让用户选目录直存 D 盘，不支持则回退普通下载）。适配不同浏览器与使用习惯。

## Background / 现状

- 图片以 base64 内嵌在 IndexedDB（数据库 `evidence-collector-db`），随项目文档整体保存（见 `src/utils/db.ts`、`src/utils/imageFiles.ts`）。
- `electron/main.cjs` 未调用 `app.setPath('userData', ...)`，走 Electron 默认：`%APPDATA%\<应用名>\`，必然在 C 盘；`IndexedDB/` 子目录随图片增多而膨胀。
- 打包目标是 electron-builder `portable`，运行时解压到系统临时目录，因此“数据放程序同级目录”不可行（临时路径 + 易随更新误删）。
- Web / 云平台模式的数据在**浏览器自己的 IndexedDB**，位置由浏览器决定，网页 JS **无法迁移**它；但可以做“用量可视 + 引导离线备份到非 C 盘 + 导出时可选保存目录”。
- 现有导出（数据包 zip、加密 `.evidence`、Word）走 `<a download>`（`downloadBlob`），落浏览器默认下载目录（通常 C 盘），尚未使用 File System Access API。

## Scope

### In scope — 桌面 Electron 版

- 启动时可从一个稳定的“指针配置”读取用户自选的数据目录，并在 `app` 就绪前 `app.setPath('userData', 目标)`。
- 应用内提供可视化“数据存储位置”设置：显示当前实际目录、通过原生文件夹选择框更改目录。
- 更改目录时把现有数据**复制**到新目录（保留原目录作为备份，不删除），写入指针配置，提示需要重启并自动重启生效。
- 提供“恢复默认位置”入口（指回 `%APPDATA%`）。
- 目标目录不可用（盘符不存在 / 无写权限 / 可移动盘未接入）时，安全回退并明确告警，绝不静默丢数据或导致应用起不来。

### In scope — Web / 云平台版（A + B）

- **A 用量可视 + 导出清理引导**：用 `navigator.storage.estimate()` 展示浏览器已占用 / 配额，用量偏高时告警，并引导“先导出到非 C 盘，再删除旧项目”释放空间。
- **B 导出/备份可选保存位置**：导出数据包 / 加密包 / Word 时，若浏览器支持 File System Access API（`showSaveFilePicker`），弹原生保存框让用户选目录（可直存 D 盘）；不支持则**优雅回退**到现有 `<a download>` 行为，并提示可在浏览器设置里改下载目录 / 开启“每次询问保存位置”。
- 用一个偏好开关（localStorage）尊重不同习惯：支持时默认“导出前询问保存位置”，可关闭改为快速下载。

### Out of scope

- 迁移浏览器 IndexedDB 本体到其他盘（网页 JS 不可行）。
- Web 版用 File System Access API 把图片**外置为文件**直存目录（即方案 C，本任务不做）。
- 把图片改为独立文件存储、或压缩 base64 体积等存储格式重构（另立任务）。
- 自动清理 / 配额管理 / 旧数据自动删除。

## Requirements

### 功能

- R1 指针配置：在一个**永远稳定、不随 userData 迁移而移动**的位置（默认 userData 计算出的 `%APPDATA%\<应用名>\` 下）存一个小 JSON，仅记录用户选择的数据目录路径。指针本体只有几 KB，不膨胀。
- R2 启动应用指针：在 `app.whenReady()` 之前读取指针；若指定了自定义且可用，则 `app.setPath('userData', 目标)`；否则用默认。
- R3 更改目录：设置界面弹**原生文件夹选择框**；用户确认后主进程把当前 userData 内容（含 `IndexedDB`、`Local Storage` 等）复制到新目录，写指针，提示“需重启生效”，随后 `app.relaunch()` + 退出。原目录数据转为**临时备份**（不立即删）。
- R4 恢复默认：一键把指针清回默认 `%APPDATA%`，同样走复制 + 重启流程；被替换下来的目录同样转为临时备份。
- R5 当前位置可见：设置界面显示“当前数据实际存储目录”的真实绝对路径，便于用户核对与备份。
- R5b 备份保留期与自动清理：迁移后旧数据仅作为**短期安全备份保留 N 天（默认 7 天）**，到期在启动时自动清理，避免长期占用两份空间导致“迁移=没迁移”。设置界面显示备份是否存在、剩余天数，并提供“立即删除备份”按钮。清理只针对本工具记录的备份，绝不误删无关文件。

### 功能 — Web 版

- R6 用量展示：Web 模式的存储设置面板显示 `navigator.storage.estimate()` 的已用 / 配额（人类可读，如 MB/GB），不支持该 API 时显示“当前浏览器不支持用量查询”。
- R7 用量告警与引导：用量占配额比例偏高（阈值可定，如 ≥80%）时以显著样式提示，并给出“导出备份 + 删除旧项目”的操作引导（复用现有导出与删除项目功能，不新造数据流程）。
- R8 导出可选保存位置：导出走统一的 `saveBlob(blob, filename)`；支持 `showSaveFilePicker` 时按偏好弹原生保存框，用户可选任意盘目录；不支持或用户关闭偏好或取消选择时回退 `<a download>`。用户在原生保存框点取消视为放弃本次导出，不报错、不回退强存。
- R9 保存位置偏好：提供“导出时询问保存位置”开关（localStorage 持久化），默认在支持的浏览器上开启；Web 存储设置面板可切换。

### 约束 / 非功能

- C1 默认零变化：未做任何设置的用户，行为与现状完全一致（数据仍在 `%APPDATA%`），升级不产生迁移、不需要用户干预。
- C2 不丢数据：迁移采用“先复制成功、再把原目录转为备份”；任何失败分支下原数据完好、指针不写、位置不切换。备份是**短期**的（默认 7 天）——保证迁移刚完成的安全窗口内可回退，又不长期占用 C 盘。
- C3 安全回退：指针指向的目录在启动时不可用时，回退默认位置并显式告警（而非静默使用默认导致“数据不见了”的错觉）。
- C4 双轨入口：同一个“存储设置”入口按环境自适应——Electron（检测 `window.evidenceData` 桥接）显示“数据存储位置（迁移/恢复默认）”；纯 Web 显示“用量 + 导出保存位置偏好”。桌面迁移 UI 不得出现在 Web，Web 用量面板不与桌面迁移逻辑耦合。
- C5 安全边界：新增 IPC 遵循现有 `main.cjs` 的 `isExpectedRenderer` 校验风格；文件夹选择与复制在主进程完成，渲染进程只发起请求。
- C6 中文界面与提示，非阻塞提示用现有 `useToast()`，二次确认用 `useConfirmDialog()`。

## Acceptance Criteria

- [ ] AC1 未设置自定义目录时，数据仍写入 `%APPDATA%\<应用名>\IndexedDB\`，与现状一致（回归无变化）。
- [ ] AC2 在设置界面能看到“当前数据存储目录”的真实绝对路径。
- [ ] AC3 通过文件夹选择框选一个非 C 盘目录并确认后，应用把现有数据复制过去、写入指针、自动重启；重启后新项目/图片写入**新目录**，且**原有项目与图片全部可见**。
- [ ] AC4 迁移后原 `%APPDATA%` 数据作为**临时备份**保留（迁移刚完成时仍在），设置界面显示备份剩余天数。
- [ ] AC4b 备份超过保留期（默认 7 天）后，下次启动时被自动清理；且“立即删除备份”按钮可手动清掉备份并即时反映在界面上。清理不影响当前正在使用的数据目录。
- [ ] AC5 手动把指针指向一个不存在的目录后启动，应用不崩溃、回退默认位置并给出明确告警。
- [ ] AC6 “恢复默认位置”后重启，数据目录回到 `%APPDATA%`。
- [ ] AC7 Web / 浏览器模式下不显示桌面“迁移数据目录”UI；改为显示存储用量与导出保存位置偏好面板。
- [ ] AC8 Web 模式下存储设置面板能显示 `navigator.storage.estimate()` 的已用 / 配额（在支持的浏览器上为真实数值）；不支持时有明确降级文案。
- [ ] AC9 在支持 `showSaveFilePicker` 的浏览器（Chrome/Edge + HTTPS/localhost）导出时，能弹原生保存框选目录并把文件写入所选位置；关闭“询问保存位置”偏好或在不支持的浏览器中，导出回退为普通下载且功能正常。
- [ ] AC10 原生保存框被用户取消时，不产生报错、不重复下载。
- [ ] AC11 `npm run build`（或项目既有构建/校验命令）通过；新增/调整的 verify 脚本（若有）通过。

## Notes

- 复用 `db.ts` 现有数据库结构，本任务不改数据库 schema，只改“数据库文件落在哪个 userData 目录”。
- 迁移“需重启”是因为 IndexedDB 在运行期已被打开，`setPath('userData')` 只能在启动早期生效。
