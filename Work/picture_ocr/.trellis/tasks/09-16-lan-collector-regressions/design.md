# 技术设计

状态：用户已批准并实施，隔离双端验证通过。电脑与手机锁屏均在范围内；本次使用页面冻结/网络故障模拟，未把受控复现等同现场 OS 锁屏根因。

## 现有链路与边界
手机 `LanMobileCollector` → `lanUpload` → Web PowerShell / Electron LAN 服务 → Web `lanBridge` 轮询或 Electron IPC → App 分流保存 → IndexedDB 事务完成 → 服务确认 → 手机核对结果。名称由 `buildGroupSnapshot` 生成，经同一会话更新传到手机。

## 1. 上传后台与恢复
先补足生产配置下的复现证据，分别标记请求接收、桥接交付、事务提交、确认回执和手机结果读取的时间与上传身份，确定停在哪一段。测试只使用隔离数据与端口；不得记录 token、照片正文或 Base64。

验收矩阵覆盖双方前台、仅电脑锁屏、仅手机锁屏和双方锁屏；双方锁屏场景分别检查电脑先恢复、手机先恢复。将锁屏前已发出/锁屏后继续上传、等待保存回执时手机锁屏作为关键时点。电脑自动锁屏是正常使用条件，不以要求用户关闭自动锁屏作为修复。系统睡眠或浏览器进程回收单列边界，不擅自修改系统电源设置；页面暂停模拟与真实锁屏实测分别记录。

已选择并验证的实现：
- 手机通过 visibilitychange/pageshow/online 合并执行原身份状态核对；旧请求执行中只标记一次待核对，结算后执行。自动模式不发 POST。
- 手机持续前台而电脑暂停时，`unconfirmed` 每 5 秒串行只读查询；隐藏、离线或手动操作中跳过，失败保持原图与界面，明确保存失败转人工重试。token 更换、放弃、成功、卸载时清理请求和定时器。
- Web 原轮询和 Electron 原 IPC 在解冻后可完成保存，未改生产后台节流策略、服务协议或超时。实验定位的缺口是手机未持续核对迟到保存结果，不能据此判定所有现场断网原因。

规划时评估的候选分支：
- 手机暂停：检查绝对截止时间到期后当前原图、原身份及未确认状态是否保留。优先在回到前台/网络恢复后合并执行一次状态核对；避免与现有操作并发、重复 POST，token 改变和卸载时取消旧任务。
- Web 电脑页暂停：验证 700ms 轮询及确认重试是否被节流、冻结。恢复时唤醒原轮询/确认链路；不能仅增加定时器频率或隐藏超时。浏览器彻底冻结时不能承诺实时 IDB 保存，恢复后完成核对才算成功。
- Electron 后台：以正式 main/preload 配置验证渲染进程接收与保存；只有证据显示后台节流阻止保存时才考虑会话期间关闭节流，并在停止/退出时恢复。不能拿测试入口关闭节流的结果替代生产验证。
- 传输服务异常：只有定位到具体 header/body/response 阶段的缺陷才修改对应服务。空请求头连接关闭可属于正常断开；日志分类不得吞掉有请求上下文的实际失败。

继续遵循 `lan-upload.md`：稳定身份、服务接收不等于保存、明确未接收/明确失败才可重发、迟到事务完成需可核对。生产超时不是首选调整点。若证明需要服务常驻写入或改变睡眠策略，回到规划审阅，不自行扩大架构范围。

## 2. 名称来源与刷新
- 复用 `loadProjectGroup(groupId)`，有真实组时以其最新 `projectName` 为权威；启动时传入的展示标题不应永久盖住数据库中的新名字。
- 无组的独立系统保持既有系统名称回退；确实未命名才显示占位。缺组记录不能被“修复”为新组或写回数据。
- 工作台 `onProjectSaved` 与列表新增 `onProjectMetadataSaved` 在实际保存完成后触发快照重建；不重挂载列表。沿用 App 会话管理，构建代际拒绝过期异步结果。对话框初始重复报告 running=false 不作废首次构建，状态真正变化才作废。
- 名称修复不改变系统列表、项目 ID 或上传目标；组级采集范围仍包括未被搜索裁剪的全部系统。

## 3. 相机入口
- 沿用当前来源对话框和样式，按 `isSecureContext` 及 `navigator.mediaDevices?.getUserMedia` 能力选择入口，不以 Chrome UA 字符串作为能力判断。
- 网页相机明确不可用时，在“拍照”点击的同步用户手势中触发现有 `capture="environment"` 文件 input，避免异步回退失去用户激活而需要再点一次。
- 可用时保留现有网页预览、拍照编码与资源清理。权限拒绝等异步失败保留明确提示及人工系统相机回退；不得自动重复申请权限。
- 取消不建立上传任务；拍摄成功沿用当前压缩、稳定身份和保存流程。触控目标维持至少 44px，键盘及焦点返回可用。

## 兼容性与回退
不改 DB 版本及持久化形态。优先维持现有 LAN 协议；若需协议字段必须双端兼容且重新审阅。按上传、名称、拍照分别回退代码，不回退数据库或清理用户记录。生产 Web 端口保持 51730。
