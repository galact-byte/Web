# 局域网采集回归排查

## 目标
恢复手机局域网采集的上传可靠性、项目组名称展示及 Chrome 拍照操作的一致性，覆盖 Web 与 Electron 两种服务。

## 背景与授权
用户报告锁屏时照片有时同步成功、有时显示 `Failed to fetch`，同时看到 `[CONNECTION CLOSED] phase=header path=unknown timeout=False`；填写名称后手机仍显示“未命名项目组”；Chrome 选择谷歌连接方式后拍照需要再次选择。用户进一步说明电脑和手机锁屏两种情况都有，电脑会自动锁屏；因此两端锁屏及组合恢复均纳入范围，优先排查电脑自动锁屏。该说明不代表已确认电脑进入睡眠。

用户已批准创建、规划，并以“可以，请继续吧”批准实施；任务已启动。证据详见 [排查记录](research/findings.md) 与 [验证记录](verification.md)。

## 需求与验收

### R1 锁屏上传可靠性（最高优先级）
- 核对 v0.8.2 前后行为，区分电脑锁屏、手机锁屏、主机睡眠和实际断网，不以通用连接日志推断某张照片是否保存。
- 主机保持运行、网络可用时，锁屏/切后台不应无故中断采集；需要恢复前台才能继续时，清楚展示待确认状态并可继续核对。
- 网络中断或后台暂停时保留当前原图与原上传身份；恢复后核对真实结果，不能重复入库、误投系统或提前报成功。
- A1：隔离双端运行，覆盖电脑/手机均前台、仅电脑锁屏、仅手机锁屏、两边均锁屏及分别恢复，并覆盖响应丢失、回执延迟与断网；恢复后同一照片最多一条引用/图片字节记录，实际事务提交后才显示成功。
- A2：测试不得通过关闭后台节流或加长生产超时掩盖本问题；模拟与真实锁屏证据分开记录，现场原因未证实时明确说明。

### R2 正确显示项目名称
- 从项目列表及系统工作台启动采集都显示当前项目组的已保存名称；改名后同一采集会话更新名称。
- 独立系统、空名称、单系统组与多系统组具有一致合理的回退显示，不改变组归属或采集范围。
- A3：验证两种启动入口、启动前/会话中改名、多系统组、单系统组及独立系统；手机会话响应与页头一致。
- 已确认缺口：`src/App.tsx:224` 工作台初始化只传空组名；`src/utils/lanGroupSnapshot.ts:43` 不读取组记录，多系统时回退占位名。

### R3 Chrome 拍照不重复选择
- 保留既有两种图片来源方式；Chrome 分开选择模式下，点击“拍照”后直接进入当前环境可用的相机入口。
- 已知网页相机不支持的环境不先进入注定失败的预览再要求第二次点击。浏览器/系统必需的权限与来源弹窗不伪装成可省略步骤。
- A4：验证普通局域网 HTTP、安全上下文、API 缺失、权限拒绝、取消拍照/选图及重复进入；不重复弹应用来源菜单、不重复上传、取消后仍可使用。
- 已确认缺口：`src/components/LanMobileCollector.tsx:169` 在相机打开失败后返回来源对话框；该流程在 v0.8.2 之前已存在。

## 约束与非目标
- 保留上传 requestId/sessionId/attempt、真实落库确认、未完成写入保护和错误采集契约。
- 不操作用户真实数据库、不清库、不删除异常记录、不改变固定 Web 端口 51730。
- 不引入依赖、数据库迁移、原生相机应用或另一套服务架构。
- 不承诺操作系统挂起或进程回收期间仍能传输；不做 UI 重设计。
- 用户已进一步批准提交、推送及发布 Release；本次按修复版本 v0.8.3 发布。
