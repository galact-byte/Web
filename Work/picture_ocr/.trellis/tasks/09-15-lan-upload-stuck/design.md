# 技术设计：局域网上传故障恢复

## 1. 边界与选择

依据 PRD R1–R7，保留现有 Web PowerShell 宿主和 Electron Node 宿主，落库仍由 React 经 IndexedDB 完成。局域网服务不另存用户项目；不替换为需要安装 Node 的 Web 启动器，不改变默认端口 51730。

Web 的首要修复是网络 I/O 不阻塞主调度；手机超时与稳定请求编号构成恢复机制；两端共同保留真实保存确认。仅加大重试或延长 timeout 不能消除已复现阻塞，也不能解决确认丢失时重复入库。

## 2. Web 请求收发

- 将“accept 后同步读完整请求”改为有界连接状态处理；各连接独立异步接收头和正文，准备好后交回 PowerShell 主循环调用既有 Handle-Control/Handle-TokenApi/Serve-Static。
- 首选 Windows PowerShell 5.1 可用的 .NET NetworkStream 异步 API；复杂的字节状态处理可用脚本内 Add-Type 的小型 C# 帮助类承载，不增加外部包或漏装的发布文件。业务会话状态仍只在 PowerShell 主循环修改，不引入跨 runspace 共享状态。
- 响应发送也独立异步并带时限；不能只修读，却被不读响应的客户端卡住。主循环及时回收已完成/失败连接，不在会话锁里等待网络。
- 保留头 32KiB、图片 10MiB、待保存 8 张的上限；连接池建议 32 个，并为 loopback 控制保留名额。满额明确关闭/拒绝新连接，不无限排队。
- 初始时限建议头 5 秒、正文总时限 45 秒、响应总时限 10 秒；持续小包也不得延长总截止时间。数值集中命名并可在测试夹具缩短。
- 验证 Content-Length 非负且在上限内，明确拒绝不支持或冲突的 framing（例如 Transfer-Encoding 与 Content-Length 冲突）；接收不完整数据不得入待保存队列。
- 每条连接独立 request/phase/计时信息；头尚未完整时路径写“未知”。reset/EOF/超时只结束当前连接，绝不沿用上一条 request。连接故障与程序处理错误分级输出。

## 3. 统一上传编号与确认语义

### 请求身份

手机为当前一张待传图片生成稳定 requestId，连同 token 和 projectId/assetId/itemId 固定保存，所有重试复用。HTTP 局域网页面不能假设 crypto.randomUUID/subtle 可用，使用可用的 crypto.getRandomValues 生成编号。服务端校验格式和长度。

服务端按“当前会话 + requestId”索引。首次完整接收并校验后记录目标、MIME、内容指纹（服务器原生 SHA-256）和状态；同编号不同目标或内容返回 409；同编号同内容返回既有状态而不重复投递。App 继续用 `lan-${requestId}` 写图，最大限度复用现有去重能力。

上传接口保留既有路径与 token/目标参数，新增请求编号参数/头（实施时两端统一）。新客户端在上传前通过快照的可选能力字段确认恢复协议可用。旧客户端无编号时服务端仍生成编号；旧客户端收到的 201/202 语义保持兼容。

### 状态

| 状态 | API 表现 | 手机行为 |
| --- | --- | --- |
| 未接收 | 状态查询 404，附明确 not_received 码 | 同一有效会话可用同 id 发送保留的字节 |
| 已接收/排队/保存中 | 202 + requestId | 等待或暂停主动等待；不重复派发落库 |
| 已保存 | 201 + requestId | 显示成功、清理待传字节、刷新权威快照 |
| 明确保存失败 | 错误响应 + failed 状态/原因 | 显示原因；人工重试才允许同 id 再入队 |
| 无法确认 | 客户端超时/断线；服务若失去保存回执则 unknown | 保留照片，提供重新核对；不能称“没保存” |
| 会话失效 | 401/409 + 明确会话错误 | 保留原图供下载，不自动换会话重传 |

Web 复用 `/api/upload-status`；Electron 对新协议请求也先受理返回 202，再查询保存结果，旧客户端无稳定编号保留同步 201 路径。主进程透传服务端 requestId，避免再次生成新编号。

同会话已完成的轻量状态保留到会话结束，图片字节在保存终态后释放；建议轻量请求元数据上限 4096，达到上限明确拒绝新任务（不驱逐旧身份后误重传）。失败重试由手机保留字节，服务不无限保留失败图片。未确认条目继续受待保存 8 张限额约束。停止会话清理对应状态，迟到 IPC/控制确认不能影响新会话。

重复 `/api/control/confirm` 若结果一致返回成功；冲突结果不能覆盖既有成功。控制桥确认重试有单次时限和会话世代校验，404/失效等终态停止重试；暂时失败后再送原结果，不重复执行保存。

## 4. 手机状态与资源生命周期

复用现有组件和 Tailwind 样式，增加单张 pending 对象和小型请求帮助函数，不构建离线任务系统。

- 阶段：处理图片 → 上传 → 等待电脑保存 → 成功 / 失败 / 尚未确认。
- 待处理对象保存原始 File/Blob、压缩后字节、requestId、会话与原始目标、阶段。异步回调须检查任务世代，token 切换/卸载主动 abort，清理计时器、object URL 和媒体流。
- 初始预算：处理图片 15 秒、上传 45 秒、单次状态/快照/控制请求 8 秒、前台保存等待 30 秒。所有 HTTP 预算涵盖响应体解析，不只到 headers；保存等待到期显示“尚未确认”，并非判定失败。浏览器后台计时器可能被节流，恢复前台按实际截止时间结算。
- 图像解码/编码超时兜底保留原图；不能只 Promise.race 后放任迟到 bitmap/URL 泄漏。可给共享压缩函数增加可选 signal/预算并保留现有调用契约，验证所有入口未退化。
- 失败/不确定时显示原目标、简短原因与主操作“重试/核对保存结果”，次操作“保存原图”。在结果尚未解决时不允许新选图悄悄替换当前图片；用户主动放弃当前待处理图要明确确认，说明这不会取消电脑端可能已经开始的保存。
- 不承诺刷新或关闭后恢复；本页图片保留只在页面仍存活时有效，离开前可普通 `<a download>` 下载原图。不能调用 showSaveFilePicker。
- 成功计数从快照刷新，不再和两秒轮询同时无条件 +1；已保存而快照暂时未刷新时保持成功，不把计数刷新失败当作上传失败。
- 清晰的行内状态、role=status/alert、可见焦点、至少 44px 触控区；375/768/1440px 校验。此处为功能型界面，沿用原有字体、边框、间距和按钮层级，不引入新视觉主题。

## 5. 电脑保存与未完成写入

两端仍复用 App 的目标系统分流与 addImageToProject 三 store 原子事务。保存完成后才发 success，重复 id 不新增引用。

当前 withTimeout 不取消底层事务，不能将其拒绝直接解释为确定失败。本任务仅针对 addImageToProject 的必要边界收敛：写事务超时尝试 abort，并以真实 oncomplete/onabort 确定终态；trackWrite 覆盖到实际事务终结，不能在包装超时后提前归零。其余数据库路径不顺手重构。若 IPC 等待超时而事务仍执行，上传状态为尚未确认，保留迟到结果处理；不以 20 秒定时器删除唯一回执关联。

Web pending 请求有超时、finally 释放 pollInFlight、停止后的 generation 校验；同一请求被重新领取仍使用稳定 image id。保存 failure 或未知结果须通过现有 errorLog 记录 requestId/目标/阶段，不含图片数据和 token。

## 6. 兼容、发布与回退

- 不改变 IndexedDB 版本或存储 key，不改 Web 默认端口和 Electron 数据目录。
- 新旧前端兼容通过服务能力字段和无 id 旧路径处理；新客户端遇到旧宿主只提供有限超时与“无法核对，请刷新/重启同版本应用”提示，不冒称支持安全自动重传。
- Windows PowerShell 5.1 继续支持。若使用独立 helper 文件，必须追加核对 Release ZIP 复制清单；优先内嵌 helper 避免增加部署耦合。
- 以任务修改集合整体回退，不做用户数据迁移。当前阶段不发版、不提交或推送；实施完成后再按项目惯例记录 CHANGES 和必要 spec 契约。
