# 修复手机局域网拍照与相册上传卡在同步中

## 目标

手机拍照或相册选图后，电脑能可靠保存；遇到传输中断或电脑无响应时，用户能看到明确状态、保留当前照片并恢复操作，不再反复卡在“正在同步”。

## 背景与证据

- 用户多次故障集中在“政务服务中心”系统；拍照与相册入口均出现，热点距电脑很近。终端出现多条 `ReadByte` / `An existing connection was forcibly closed by the remote host`，对应 Web ZIP PowerShell 服务读取请求头时连接被对端关闭。
- 隔离运行原版 `start-server.ps1` 已复现：空闲 TCP 连接让正常控制请求超过 2516ms 仍无响应，关闭该连接后 57ms 恢复，并产生同类日志。尚未还原现场断连诱因，也未读取或修改该系统真实数据。
- 完整证据、可重复命令和限制见 `research/findings.md`，基线脚本为 `research/reproduce-web-head-of-line.mjs`。

## 验收标准

- A1 → R1：对真实 PowerShell 隔离服务注入空闲连接、未完成头、未完成正文、连接 reset 和慢读响应；其他正常状态/上传确认请求仍能在 2 秒内完成。故障连接有总时限、并发数与大小边界，单连接故障不终止服务。
- A2 → R2/R3：拍照与相册实际走同一恢复流程；图像处理或网络挂起在约定时限进入可操作状态，保留当前图片；原图下载走普通浏览器下载。切后台恢复后不出现永久 busy 或迟到回调覆盖新状态。
- A3 → R4/R5：两端分别测试上传已接收但响应丢失、保存已成功但确认丢失、重复提交、重复确认和延迟提交，数据库最多一份图片引用/字节，UI 不重复累加数量。目标切换或删除时不误投。
- A4 → R5/R6：数据库真实失败、电脑页面不可用、会话停止/过期、服务断开均有明确状态；未知结果不报成功或确定未保存；恢复后可继续核对或同 id 重试。确认轮询不会被一条挂起请求永久锁住。
- A5 → R7：隔离测试日志可对账阶段和请求，且不含 token/base64；无关的连接 reset 不冒充图片保存失败。
- A6 → 全部：运行相称自动化、真实 PowerShell/浏览器/Electron 隔离回归、构建与差异检查。375/768/1440px 检查恢复入口、键盘焦点、状态播报与布局。真实手机/热点未测试时如实标注。

## 约束与范围外

- 同时覆盖 Web ZIP 和 Electron，沿用现有采集页视觉和应用存储结构。
- 保持 Web 默认来源 `http://127.0.0.1:51730/`、现有白名单/会话验证、CSP、图片压缩策略、三 store 原子写入和 `trackWrite` 关闭保护；不新增运行时依赖或要求用户安装 Node。
- 不读写真实用户库，不删除异常记录，不推断已有图片已经找回；本次无数据迁移和发版。
- 仅保留当前页单张待处理图片；跨刷新/关闭/浏览器回收恢复、全量离线队列和自动跨会话重传不在本次范围。离开前可保存原图，明确提示内存保留限制。
